Speed and Number Plates

One camera stream is enough to track a vehicle, read its plate, and estimate speed from how it moves through the frame.

YOLOSORTTrOCR

Question

  • Can a single video identify a vehicle and say how fast it is going?
  • Plates are small, motion is noisy, and the same car must stay one identity across frames.

Method

  • YOLO finds vehicles and plates. SORT keeps identities.
  • TrOCR reads the plate crop.
  • Speed comes from tracked displacement. A FastAPI route serves the annotated video.

Evidence

41 km/hsample track, id 3
37 km/hsample track, id 5
1 streambrowser video feed

What the result actually says

  • Vehicles use YOLOv8n trained on COCO. Plates use a second YOLOv8n, custom-trained, around mAP50 0.95.
  • SORT keeps one identity across frames. Speed is displacement of that track. On the sample clip, id 3 reads 41 km/h and id 5 reads 37 km/h.
  • The same pipeline was packed in Docker and run on Azure Container Instances against a live camera stream.

What it does not show

  • TrOCR, after fine-tuning, fuzzy-matches the plate about 50–60% of the time. Exact character match is lower. A blurry crop still fails.
  • Speed jitters between frames. The number needs smoothing before anyone would trust it as a measurement.

Beside the other attempts

  • Detection is the strong half. OCR is the weak half. The tracker is what makes speed possible at all.
  • The default file is the UHD sample in data/videos. VIDEO_SOURCE can be another file, a stream URL, or 0 for the webcam.

Stack

YOLOv8n, SORT, TrOCR, FastAPI. Weights load from plate_detection_env, which matches those checkpoints.
